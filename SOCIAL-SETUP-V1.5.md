# SCENA V1.5 — подключение Facebook и Instagram

Инструкция для оператора. Дата сверки кода: 6 сентября 2026 года.

**ПОДТВЕРЖДЕНО:** локальный модуль подготовки и адаптеры реализованы. Проверки выполнены с подменой внешнего HTTP, без отправки реальных публикаций.

**НЕ ПРОВЕРЕНО:** разрешения конкретного приложения Meta, его App Review/режим доступа, действительность аккаунтов и токенов, реальная отправка и доступность публичных файлов. Этот документ не является актом приёмки рабочего подключения.

## Что поддерживает версия

| Площадка | Поддержка SCENA V1.5 |
|---|---|
| Facebook | Одна фотография JPEG с подписью на управляемой Facebook Page; личные профили не поддерживаются |
| Instagram | Одна фотография JPEG с подписью в профессиональном аккаунте Business/Creator через Instagram Login |

В интерфейсе и адаптерах подпись ограничена 2200 символами, включая ссылку обратно в SCENA. Карусель внутри «Моей Сцены» является отдельным элементом: отправки каруселей, Stories, Reels и видео в соцсети в V1.5 нет. TikTok исключён.

## Пока продукт работает локально

В кабинете можно сохранять варианты подписей для Facebook и Instagram, выбирать RU/RO и скачивать ZIP: `scena-publication.jpg` и `caption.txt`. Оригинал фотографии и база данных в этот ZIP не попадают.

Подготовленное изображение создаётся редактором публикаций отдельно от оригинала: JPEG 1080×1350 с аккуратным лейблом SCENA. Файл находится в `media/publications/<идентификатор>/scena-publication.jpg`. Внешняя ссылка на фотографию не скачивается модулем для включения в ZIP.

`localhost`, локальный путь Windows и локальный IP недоступны серверам Meta. Если публичный адрес сайта не задан, личная ссылка в экспортируемую подпись не добавляется и прямая отправка недоступна. Сам ZIP можно использовать для ручного размещения.

## Подготовка оператором

1. В своём приложении Meta выберите и проверьте поддерживаемую версию Graph API. Установите её явно; автоматического выбора «последней версии» в SCENA нет. Совместимость выбранной версии нужно подтвердить перед рабочим подключением.
2. Для Facebook получите **Page Access Token именно нужной страницы**, а не токен личного пользователя. По актуальной документации Pages API проверьте требования к `pages_manage_posts`, `pages_read_engagement` и доступным задачам управления/создания контента. Не выдавайте дополнительные разрешения без необходимости. При получении списка управляемых страниц отдельно сверяйте требования соответствующего процесса входа.
3. Для Instagram используйте профессиональный аккаунт и **Instagram User Access Token через Instagram Login** с разрешениями `instagram_business_basic` и `instagram_business_content_publish`. Этот адаптер обращается к `graph.instagram.com`; токен другого процесса входа нельзя считать взаимозаменяемым. Связка Instagram Login сама по себе не требует привязанной Facebook Page.
4. Проверьте в Meta Dashboard нужный режим и уровень доступа приложения для реальных клиентов. Встроенного OAuth-подключения, автоматического получения/продления токенов и прохождения App Review в V1.5 нет.
5. Передайте параметры процессу запуска SCENA через окружение операционной системы или используемое оператором средство управления секретами. Перезапустите экземпляр SCENA, чтобы он получил новые параметры.

| Переменная окружения | Что задать |
|---|---|
| `SCENA_META_API_VERSION` | Проверенную версию в формате `v<номер>.0`; обязательна для обеих площадок |
| `SCENA_FACEBOOK_PAGE_ID` | Числовой ID целевой Facebook Page |
| `SCENA_FACEBOOK_PAGE_TOKEN` | Page Access Token этой страницы |
| `SCENA_INSTAGRAM_ACCOUNT_ID` | Числовой ID профессионального Instagram-аккаунта из процесса Instagram Login |
| `SCENA_INSTAGRAM_ACCESS_TOKEN` | Instagram User Access Token этого аккаунта |

Настраивать обе площадки одновременно необязательно. Значения секретов не вводятся в формы кабинета, не записываются в SQLite или ZIP, не добавляются к ссылкам, README и снимкам экрана. Статус конфигурации показывает только ID, версию API и технический отпечаток настройки. Наличие конфигурации ещё не означает работающее подключение.

## Публичные адреса

Оператор размещает сайт владельца по публичному HTTPS-адресу и указывает его в существующей настройке адреса сайта (`public_base_url`, раздел QR). Приложение строит ссылку на конкретный пост: `?page=post&post=<public_id>&lang=ru|ro`.

Отдельно разместите **тот самый подготовленный JPEG с лейблом SCENA** на публичном сервере. В варианте соцсети откройте «Для оператора: публичный адрес фотографии» и вставьте прямую HTTPS-ссылку на `.jpg` или `.jpeg`. Она должна открывать сам файл без входа в аккаунт. Не подменяйте его оригиналом, другой фотографией или изменяемым файлом после подтверждения.

Пилот не загружает фотографии на публичный хостинг автоматически. Проверка URL в коде проверяет его форму и исключает локальные адреса, IP-литералы, пользовательские реквизиты и секретные параметры; она **не подтверждает** доступность файла для Meta или совпадение его байтов с локальной версией. За размещение нужного файла и его сохранность отвечает оператор. В точном предпросмотре показывается публичная ссылка изображения, которая будет передана площадке.

## Путь владельца после подключения

1. Сначала опубликовать материал в своей Сцене. Неопубликованные изменения основного поста в отправку не подставляются.
2. Выбрать Facebook или Instagram, язык, проверить подпись и нажать «Сохранить вариант».
3. Нажать «Проверить аккаунт». Это отдельный запрос чтения `/me`: он сопоставляет владельца токена с настроенным ID и показывает имя. Успешная проверка личности не подтверждает все права на публикацию.
4. Нажать «Посмотреть перед отправкой»: сохранить точный снимок фотографии, подписи со ссылкой, аккаунта и опубликованной версии. Подготовка не отправляет материал в Meta.
5. Проверить снимок, актуальность цены/условий и адрес аккаунта, поставить подтверждение и нажать «Отправить в Facebook/Instagram».
6. Проверить результат и ссылку в истории. Для второй площадки подготовить и подтвердить её вариант отдельно.

Изменение аккаунта, токена или версии API делает прежнее подтверждение конфигурации недействительным. Изменение опубликованного поста блокирует отправку устаревшего снимка. Открытие кабинета, сохранение черновика, локальная публикация и перезапуск не вызывают отправок в соцсети.

## Статусы и дальнейшие действия

| Статус | Значение и действие |
|---|---|
| Не подключено (`not_configured`) | Параметров нет или они неполны. Использовать подготовку/скачивание; оператор завершает настройку |
| Подготовлено (`prepared`) | Есть сохранённый снимок. Внешняя отправка ещё не выполнена; требуется подтверждение |
| Обрабатывается (`processing`) | Instagram сохранил контейнер. Примерно через минуту нажать «Продолжить отправку»: проверяется существующий контейнер, и готовый материал может быть опубликован. Новая загрузка не создаётся |
| Опубликовано (`sent`) | Площадка подтвердила публикацию. Открыть полученную ссылку; если ссылка не получена, проверить аккаунт. Сбой получения ссылки не отменяет подтверждённую публикацию |
| Результат неизвестен (`unknown`) | Таймаут или неполный ответ: публикация могла состояться. Не создавать повтор вслепую. Проверить страницу; для известного Instagram-контейнера доступна проверка результата без повторного POST |
| Ошибка отправки (`failed`) | Получен определённый отказ. После устранения причины заново нажать подготовку и отдельно подтвердить отправку. Старая неудачная попытка остаётся в истории; новая связана с ней |
| Отправляется / проверяется (`sending` / `checking`) | Попытка занята. Не запускать параллельный повтор. Если состояние осталось после прерывания процесса, оператор проверяет внешнюю площадку; автоматического сброса и повторной публикации нет |

Завершённые, неизвестные и выполняющиеся отправки не превращаются автоматически в повторяемые. Для Instagram при неопределённом результате проверка может подтвердить факт публикации по контейнеру без получения постоянной ссылки; идентификатор поста при этом не выдумывается.

## Официальные источники для подключения

- [Meta: Facebook Pages — Posts](https://developers.facebook.com/docs/pages-api/posts/) — правила публикации на страницу и необходимые разрешения. Полное открытие этой страницы во время подготовки документа ограничивалось ответом 429; перед рабочим подключением оператор повторно сверяет раздел требований выбранной версии.
- [Meta: Page Photos](https://developers.facebook.com/docs/graph-api/reference/page/photos/) — фото через `/{page_id}/photos`.
- [Официальная коллекция Meta: получение Page Access Tokens](https://www.postman.com/meta/facebook/request/bqfxwbp/get-access-tokens-of-pages-you-manage) — различие User Token и токена конкретной страницы.
- [Официальная коллекция Meta: Instagram API](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api) — Instagram Login, профессиональные аккаунты, разрешения, JPEG, публичный сервер и этапы `/media` → статус контейнера → `/media_publish`.
- [Meta: Instagram Login — Get Started](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/get-started/) — получение ID/username через `/me`.

Точные рабочие аккаунты, выданные разрешения и результаты первой реальной публикации фиксируются отдельной приёмкой после согласования внешнего подключения. Реальные токены в такой отчёт не включаются.
