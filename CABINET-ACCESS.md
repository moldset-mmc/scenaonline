# Кабинет SCENA: пароль, смена и восстановление

Проверено 14 сентября 2026 года. Владелец сохранил пароль в Vercel; проверено наличие `SCENA_ADMIN_PASSWORD` типа Secret только для Preview. Значение не читалось. Новая публикация и проверка входа ещё не выполнены.

## Что работает сейчас

У сайта один вход администратора. Пароль читается из серверной переменной `SCENA_ADMIN_PASSWORD`, затем из одноимённого секрета Streamlit, если переменная отсутствует. Индивидуальных аккаунтов с паролями, подтверждения почты, кнопки «Забыли пароль» и формы смены пароля в кабинете пока нет.

На исходном коммите `d838bd5` запуск предпросмотра требует не менее 16 символов. В этом чекпойнте по запросу владельца подготовлена поддержка временного пароля от 8 символов только для изолированного предпросмотра. Значение выбранного владельцем пароля здесь намеренно не записано. Четыре локальные проверки прошли; изменение ещё не опубликовано. Запуск этого предпросмотра в Production по-прежнему запрещён.

## Установить временный пароль для проверки

1. Открыть Vercel → проект `scenaonline` → Settings → Environment Variables → Add Environment Variable.
2. Имя: `SCENA_ADMIN_PASSWORD`. Выбрать тип Secret (секретное значение). Для пробного кабинета выбрать только Preview; не менять восемь переменных облачных хранилищ.
3. Самостоятельно ввести выбранный временный пароль и сохранить. Не включать значение в GitHub, скриншоты, команды или переписку.
4. Опубликовать согласованный preview из коммита, который уже содержит поддержку восьмизначного пароля. Не перезапускать старый код с коротким паролем: его проверка отклонит запуск.
5. Дождаться READY, открыть адрес новой публикации и проверить правильный и неправильный вход, выход и повторный вход. Эта инструкция не подтверждает результат этих проверок.

Изменение переменной действует для новых развёртываний. Текущий URL с идентификатором сборки привязан к существующему предпросмотру; сохранение переменной не обновляет его автоматически. Перед рабочим запуском будет проверен постоянный домен проекта. Временный пароль с повторяющимися цифрами предназначен только для проверки без реальных данных; перед рабочим доступом замените его уникальным паролем.

## Как менять пароль владельцу

1. В том же проекте Vercel найти `SCENA_ADMIN_PASSWORD` и выбрать редактирование.
2. Задать новый уникальный пароль; для рабочей версии использовать длинный пароль, например от 16 символов. Выбрать окружение используемой публикации: Preview для пробы, Production только после завершения рабочего запуска.
3. Сохранить и выполнить согласованное новое развёртывание с актуальным кодом.
4. Проверить вход новым паролем и отказ старому в новой браузерной сессии.
5. При экстренной смене проверить также старые публикации и активные сессии. В нынешнем коде успешный вход хранится как признак в сессии Streamlit; изменение переменной само по себе не гарантирует отзыв доступа ко всем старым экземплярам. Для рабочего запуска нужен явный механизм отзыва сессий и закрытия устаревших публикаций.

## Если владелец потерял пароль сейчас

Владелец с доступом к проекту Vercel задаёт новый `SCENA_ADMIN_PASSWORD` по инструкции выше; старый пароль для этого не нужен. Содержимое базы и фотографии при такой смене удалять не требуется. Если утрачен и доступ к Vercel, сначала восстановить доступ к аккаунту Vercel через его обычный процесс или обратиться к другому уполномоченному администратору команды. Сайт SCENA пока не умеет отправить ссылку восстановления.

## Как это должно работать для будущего пользователя

Предлагаемый процесс, ещё не реализован:

1. Пользователь нажимает «Забыли пароль?» и вводит подтверждённый адрес электронной почты своего аккаунта.
2. Сайт всегда показывает одинаковое подтверждение запроса, не раскрывая, зарегистрирован ли адрес. Запросы ограничиваются по частоте.
3. На почту отправляется случайная одноразовая ссылка с коротким сроком действия, например 15 минут. В базе хранится только хеш токена.
4. Пользователь открывает ссылку, дважды вводит новый пароль. Сервер проверяет и однократно погашает токен, сохраняет стойкий хеш пароля, отзывает прежние сессии и отправляет уведомление о смене.
5. Пользователь входит с новым паролем. Старый пароль не восстанавливается и не отправляется по почте.

Для этого нужны отдельные аккаунты, подтверждение адреса, почтовый сервис, хранение хешей и токенов в постоянной базе и управление сессиями. Эти подключения и функции не входят в уже созданные три ресурса автоматически. Регистрацию почтового провайдера и реальные письма нельзя считать выполненными без отдельной настройки и проверки.
