# Заявки на услуги → Telegram, 15.09.2026

Основание: владелец подтвердил две отдельные кнопки «Связались» и «Подтвердить
запись», тот же бот, выбор канала и переход к контакту клиента. База разработки:
`3e7f68052bcc04bd0ec40a35f80a8b943243fe5f`, репозиторий
`moldset-mmc/scenaonline`, production `https://scenaonline.vercel.app`.

## Реализация

- `scena_service_telegram.py` использует существующую зашифрованную привязку,
  callback endpoint и секреты маркета. Новые инфраструктурные ресурсы не создаются.
- Аддитивные поля `requests`: `revision`, `contact_telegram` и Telegram outbox
  (`telegram_status`, attempts, retry_at, message_id). Историческим заявкам
  назначается `skipped`; новым записям на услуги — `queued` в той же транзакции.
  Уведомление отправляется после commit; потеря Telegram не теряет заявку/слот.
- Выбор канала: phone / telegram / sms / email. Контакт проверяется сервером.
  В браузере нужное поле переключается без сетевого запроса. Телефон нормализуется
  существующим валидатором Молдовы. В Telegram используется обычный текст номера.
- Callback `s:<request-id>:<revision>:<c|f>:<signature>` укладывается в 64 байта.
  Применяются секрет заголовка, проверка личного чата и владельца, 96-битная подпись,
  ID исходного сообщения и повторная проверка привязки в writer transaction.
  Подписи заявок отделены префиксом от callback товаров.
- Правила статуса общие с кабинетом. «Связались» сохраняет срок удержания.
  Подтверждение проверяет истечение, прошедшее время, пересечение слотов и ревизию.
  Поздняя/повторная кнопка не отменяет более новое решение из кабинета.
- Статус сначала фиксируется, затем редактируется тот же Telegram-лид. Повторное
  нажатие после сбоя редактирования синхронизирует сообщение без повторной мутации.
- Ссылка `/?page=admin&lang=ru&section=work&view=requests&request=<id>` открывает
  одну раскрытую заявку, контактные кнопки и её форму статуса. Авторизация и
  сохранение назначения после входа используют прежний путь кабинета.
- Telegram допускает HTTP/tg URL в inline-кнопках. Telegram-контакт ведёт прямо
  на `t.me/<username>`; phone/SMS/email ведут в защищённую карточку, где есть
  `tel:` / `sms:` / `mailto:`. Переходы не отправляют сообщение автоматически.
- SMS-события для услуг создаются только при выборе SMS; прежний API без явного
  выбора сохраняет default `sms` для обратной совместимости. Очередь не равна
  подтверждённой отправке через провайдера.
- Модуль включён в fingerprint миграций и переносимый комплект приложения.
  Зашифрованная привязка бота по-прежнему исключена из переносимых данных.

## Проверки до публикации

- 279 Python-тестов: OK, 3 существующих пропуска.
- 10 отдельных тестов услуг и Telegram повторно прошли на libSQL: каналы,
  проверки контактов, очередь/таймаут/повтор, одновременное подтверждение,
  защита владельца/подписи/сообщения, истечение/прошедшее/занятое время,
  старое сообщение после отмены, миграция исторических заявок.
- Реальный HTTP-сценарий на двух экземплярах: валидация Telegram-контакта,
  сохранение одной заявки и одного лида, переход через login, телефон/Telegram/
  SMS/email ссылки, две кнопки статуса через webhook и повтор без второй мутации.
  Прежние тесты маркета, сохранений, фото, записи и резервной копии прошли.
- DOM: переключение контакта без запросов и потери введённого значения;
  прежние проверки вкладок, повторного сохранения и галереи прошли.
- Все вызовы Telegram перехвачены тестовыми адаптерами. Рабочие клиентские
  заявки и отправки при этих проверках не создавались.

Публикация и состояние существующего подключения требуют свежей проверки после
деплоя. Получение нового лида и нажатия на телефоне владельца не подтверждены
этими тестами. Старые лиды и заявки автоматически не переотправляются.

Источник контракта: [Telegram Bot API](https://core.telegram.org/bots/api#inlinekeyboardbutton),
[ссылки Telegram](https://core.telegram.org/api/links).
