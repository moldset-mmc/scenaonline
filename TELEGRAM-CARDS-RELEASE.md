# Telegram cards and status menu — 2026-09-15

Base: `0a490f7a6bdc7cf704fc10b89fb2d442c6c81f9f`.

## Behavior

- Service and market leads use one **Сменить статус** button, a complete status
  menu with current-state marker, and **Назад**. Menu navigation never writes a
  selected status. Booking expiry continues to follow the existing clock.
- Service cards show one booking date/time line in `DD.MM.YYYY · HH:MM`, one
  timezone label, and a separate confirmation deadline in the same date format.
  Only the selected additional reply contact is shown. Empty notes are omitted.
- Removed the Telegram call button that opened the cabinet. Phone stays plain
  international text, allowing Telegram phone detection; cabinet retains `tel:`.
- The screenshot's market phone `+3737475858` is incomplete. Checkout now rejects
  `+373` numbers without eight national digits; historical input is preserved.
  No digits are invented and no unsupported `tel:` Bot API inline URL is used.
- Existing delivered cards can be edited with **Обновить карточку в Telegram**
  from the corresponding cabinet record. This calls only `editMessageText`;
  it does not resend a lead, change a business status, or contact the customer.

## Integrity

New callbacks use signed `o:` / `r:` payloads. Legacy `c:` and `s:...:c/f` remain
supported. Secret, owner, private chat, bound message ID, active binding and
record revision checks remain. A stale choice refreshes the menu for a new choice.
Concurrent identical status updates commit once; selected SMS events queue once.
All transitions that reserve a service slot now check expiry, past dates and
overlap, including reopening a closed request. The automatic expired state is
shown as automatic and cannot be set manually through the bot menu.
